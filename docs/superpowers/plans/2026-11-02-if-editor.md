# Visual `.if` Interface Editor Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A VS Code custom editor for `.if` files that shows a pixel-exact preview of the interface, lets you drag, drop and edit components through palettes and forms, and switches to and from the plain text editor.

**Architecture:**
- **Host (extension, Node):** parses the `.if` text, applies edit intents as pure text-to-text functions, and renders the interface into an `Int32Array` with a verbatim port of the Client-TS 2D drawing code. All of this is unit-testable with `node --test`.
- **Webview:** plain JS. It shows the rendered buffer on a canvas with an overlay canvas for selection and handles, and sends intents back. The host turns them into one minimal `WorkspaceEdit` on the real `TextDocument`, so undo, dirty state and the text view stay in sync.

**Tech Stack:** TypeScript 5 (`tsc`, CommonJS, ES2022), VS Code API ^1.90 (`CustomTextEditorProvider`, webview), Node 24 stdlib (`zlib.inflateSync`, `zlib.deflateSync`, `zlib.crc32`), `node:test`. No new dependencies.

**Spec:** `C:\Users\zack\.claude\plans\plan-an-interface-editor-giggly-finch.md`

## Global Constraints

- No new runtime or dev dependencies, and no bundler. Webview code is plain JS in `media/ifedit/`.
- The editor writes only exact `key=value` lines and `[name]` headers: no spaces around `=` and no comments. The packer does no trimming (`ares-rs/src/pack/name_map.rs`, `parse.rs:98`).
- Keep the file's own line endings (detect `\r\n`; Content uses `\n`). Untouched lines stay byte-identical.
- Keys, `yes` and enum words are case-sensitive. A boolean is true only for `yes`, and the editor writes `yes` and deletes the key for false.
- Pixel exactness: drawing code is ported **verbatim** from `../Client-TS/src/graphics/{Pix2D,Pix32,PixFont}.ts` and `../Client-TS/src/client/Client.ts:9899-10264`. That includes the clip quirks (e.g. `plotLetter` uses `y + h >= clipMaxY` and cuts one extra row). Editor-only marks (selection, model placeholders, inv/invtext cell outlines) are drawn on the webview overlay and never into the buffer.
- Areas: `main` 512x334, `side` 190x261, `chat` 479x96. The choice is remembered per file in `workspaceState` under `ifedit.area:<fsPath>`, default `main`.
- Model components are drawn only as overlay placeholders (a dashed box plus the model name).
- New component ids: new id = max id in `pack/interface.pack` + 1. The `id=iface:com` line is appended to the pack, and the id is inserted into `pack/interface.order` right after the last id of the interface's group.
- Never run `cargo fmt` / `rustfmt` (Task 10 touches Rust).
- Commits end with `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`.

## Review Focus

1. **Round trip on real content.** Parsing and then applying a no-op intent to any of the 197 Content `.if` files must leave the text byte-identical. Pinned by `round trip over Content` in Task 1.
2. **Duplicate keys.** The last duplicate wins in the packer. Setting a key that appears twice must change the last occurrence and remove the earlier ones, or the preview and the build disagree. Pinned in Task 2.
3. **Deleting a layer that has children.** Leftover `layer=gone` lines would fail the build ("Layer ... does not exist"). Deleting a layer deletes its descendants and their pack ids. Pinned in Task 2/3.
4. **A malformed number** (`x=12a`, `x = 5`) must not crash the renderer. It renders as 0 and appears in the warnings list. Pinned in Task 1 and Task 5.
5. **Missing assets** (unknown sprite sheet, index past the end of a sheet, `hitmarks - Copy.png`, a `.opt` that doesn't divide the image): the sprite draws nothing and the rest still renders. Pinned in Task 4.

  ```ts
  export interface KeyLine { key: string; value: string; line: number }   // 0-based line index
  export interface Com { name: string; header: number; end: number; keys: KeyLine[] } // end = exclusive line after its last non-empty line
  export interface Warning { line: number; message: string }
  export interface IfModel {
    name: string;              // file stem
    eol: "\n" | "\r\n";
    lines: string[];           // split on \n, trailing \r stripped
    root: Com;                 // name "", header -1, keys before the first header
    coms: Com[];               // file order
    children: Map<string, string[]>; // parent name ("" = root) → child names in draw order

  export function parseIf(name: string, text: string): IfModel
  export function get(com: Com, key: string): string | undefined   // last occurrence wins
  ```

The tree rules match `ares-rs/src/pack/interface.rs:142-185` exactly:
- Each header pushes its component onto the root's children.
- `layer=X` pushes the current component onto `X`'s children and removes it from the root's list.
- A `layer=` line before any header pops the root's last child.
- Empty lines are skipped.
- A line with no `=` gets key `""`.

Warnings, each with its line number:
- a key or value with leading or trailing whitespace
- a value containing `//`
- a line with no `=`
- a duplicate header
- a duplicate key inside one component
- a number key that isn't a valid packer int: `x`, `y`, `width`, `height`, `scroll`, `trans`, `zoom`, `xan`, `yan`, `clientcode`
- `layer=` naming a component that doesn't exist

**Files:**

**Interfaces:**
- Consumes: `parseIf`, `get`, `find` (Task 1)
- Produces:
  ```ts
  export type Intent =
    | { kind: "set"; com: string; key: string; value: string | null } // com "" = root; null deletes every occurrence
    | { kind: "add"; com: string; parent: string; keys: [string, string][] }
    | { kind: "delete"; com: string }                                  // also deletes descendants
    | { kind: "reorder"; com: string; parent: string; before: string | null } // reparent and/or move; before=null → last
    | { kind: "batch"; intents: Intent[] };
  export function applyIntent(ifName: string, text: string, intent: Intent): string
  export function deletedComs(ifName: string, text: string, intent: Intent): string[]  // names a delete removes, for pack edits
  export function minimalEdit(oldText: string, newText: string): { startLine: number; endLine: number; text: string } | null
  export function nextComName(model: IfModel): string   // "com_" + (max N over /^com_(\d+)$/ + 1)
  // schema.ts
  export const KEY_ORDER: string[]   // ["type","layer","x","y","width","height"] — new keys are inserted after the last present one of these, else at the end of the block
  ```

Rules:
- **set:**
  - If the key exists, rewrite its **last** occurrence in place and delete the earlier ones.
  - Otherwise insert it after the component's last `KEY_ORDER` key that comes before it in `KEY_ORDER`, else at the end of the block.
  - `null` deletes the key.
- **add:** append `"\n[name]\n" + "type=..."` lines in `KEY_ORDER`. When `parent !== ""`, add `layer=<parent>` straight after `type`. Ensure exactly one blank line between blocks.
- **delete:** remove the component's block and its descendants' blocks (`children` map, recursive), each with one adjacent blank line.
- **reorder:**
  - Moving a block moves its draw position: root children follow header order, and layer children follow `layer=` order, which is block order because each child carries its own `layer=` line.
  - Set `layer=` to `parent`, or delete it when `parent === ""`.
  - Move the block so it sits immediately before `before`'s block, or after the last block among `parent`'s children when `before` is null.
- **batch:** fold `applyIntent` over the intents, re-parsing between them.
- **minimalEdit:** compare by lines. Strip the common prefix and suffix, then return the replaced line range and the replacement text. Return `null` when the texts are equal.

  ```ts
  // png.ts
  export function decodePng(buf: Buffer): { width: number; height: number; rgba: Uint8Array }   // throws unless bit depth 8, colour type 6 (RGBA) or 2 (RGB), not interlaced
  export function encodePng(width: number, height: number, rgba: Uint8Array): Buffer
  // assets.ts
  export interface Tile { wi: number; hi: number; xof: number; yof: number; owi: number; ohi: number; pixels: Int32Array } // 0 = transparent
  export interface Font { height: number; mask: Int8Array[]; maskW: Int32Array; maskH: Int32Array; offX: Int32Array; offY: Int32Array; advance: Int32Array }
  export const FONT_NAMES: readonly ["p11_full", "p12_full", "b12_full", "q8_full"]
  export class Assets {
    constructor(contentRoot: string);
    sheetNames(): string[];                                   // sprites/*.png stems, sorted bytewise
    sheet(name: string): { tileW: number; tileH: number; cols: number; rows: number; tiles: Tile[] } | undefined;
    sprite(spec: string): Tile | undefined;                   // "name,index", split on the LAST comma (IfType.ts:252-261)
    font(id: number): Font | undefined;                       // 0..3
    invalidate(): void;                                       // drop caches
  }
  ```

Port the packer's rules (`ares-rs/src/pack/pix.rs`):
- The tile size comes from the first line of `sprites/meta/<name>.opt` (`WxH`, trimmed), or the whole image if there is no `.opt` file. If the image doesn't divide evenly, the sheet is undefined.
- Tiles are numbered row-major.
- Each tile is cropped to the bounds of its non-magenta pixels, or the whole tile if every pixel is magenta. Set `xof,yof` to the crop origin, `wi,hi` to the crop size and `owi,ohi` to the tile size.
- Pixels: magenta `0xFF00FF` becomes `0`, black `0x000000` becomes `1` (from `Pix32.depack`), and every other pixel keeps its RGB. Alpha is ignored.

Fonts: `fonts/<name>.png` with `fonts/meta/<name>.opt` (`20x20`):
- `mask[c]` holds per-pixel **signed palette indices** (`(i << 24) >> 24`).
- The palette is the packer's: magenta first, then colours in first-seen row-major order over the **whole sheet** (`pix.rs` `palette`).
- `offX`, `advance` and `height` are computed by porting `PixFont.depack` lines 56-95. That includes the `space += charMask` sums over palette indices and the space-width copy: from `'I'` (73) for `q8_full` (quill), otherwise from `'i'` (105).
- `offY[c]` is the crop top.

`render` walks the tree the way `drawInterface` does (`Client.ts:9899-10264`), starting at `drawInterface(root, 0, 0, 0)` on a `Surface(AREAS[area])`:
- **Root size:** `width`/`height` default to 512x334 unless the root keys say otherwise.
- **Hidden layers:** `hide=yes` layers are drawn only when `state.showHidden || state.hover === name`.
- **Active state:** `getIfActive(child)` becomes `state.active`.
- **Hover:** the client's "hovered" test becomes `state.hover === name`.
- **Variables:** `%1..%5` are replaced by `state.vars[0..4]` (default `["0","0","0","0","0"]`).
- **Scroll:** `scrollPos` comes from `state.scroll[name]`, clamped like the client clamps it.
- **Chat colours:** the 479-width colour swaps apply when `area === "chat"`.
- **Text:** `\n` here is the two characters backslash and `n`.
- **inv:** draws only the `slotN` background sprites. Parse `slotN=sprite,idx[:dx,dy]` the way `interface.rs:307-322` does. Inventories are empty in the preview, so no obj icons.
- **invtext:** draws nothing (no objs).
- **model:** draws nothing.
- **clientcode:** ignored.
- **Boxes:** every component visited gets a `Box`, pushed in draw order. `x,y` are absolute. `w,h` are pixels; for inv this is `cols*(32+mx)-mx` by `rows*(32+my)-my`, and for invtext `cols*(115+mx)` by `rows*(12+my)`. `clip` is the clip in effect, and `originX/Y` is the parent origin, so the webview can turn absolute coordinates back into the child's `x`/`y`.

`readConditions`:
- Mirrors the packer's count: `scripts` = the number of N in 1..5 with `scriptNop1` present.

  - `stat`: a STATS select
  - `invcom`: a datalist from `lists.interface`
  - `obj`, `varp`, `varbit`: datalists
  - `int`: a number input
- Adding or removing conditions and op rows sends `batch(writeConditions(...))`.
- Toolbar hint: the preview's **active** toggle shows the state when conditions are true.
